Sync indicator of the bfc plan detail

Issue #17. While the TUI is open it syncs the plans with GitHub every 15 seconds and after every local change. This demo lets you push that model through awkward cases and see what the status line would say. Throwaway prototype; the logic module in the page source is what moves into Go.

Rules in this model, to confirm

  1. Only one sync runs at a time. A change made during a sync is not lost: one more sync runs right after.
  2. Offline keeps all local work. Changes count up as "waiting", and the timer retries.
  3. Authentication errors count as offline, and the status shows git's own message.
  4. A conflict commits nothing (as bfc pull). The timer keeps retrying; the status stays "conflict" until a sync succeeds, for example after bfc pull --keep in another terminal or the colleague's next change.
  5. Local mode (sync.enabled: false) never syncs and says so.
