# FTS5 in modernc.org/sqlite without CGO

**Short answer: yes.** `modernc.org/sqlite` v1.62.0 (SQLite 3.54.1) is built with `SQLITE_ENABLE_FTS5` on every platform it ships, and `CGO_ENABLED=0` builds and runs FTS5 queries. Checked on 2026-11-17 for issue #15.

## Evidence

| Check | Result | Source |
|---|---|---|
| Compile flags of the transpiled SQLite | Every generated `lib/sqlite_<os>_<arch>.go` names `-DSQLITE_ENABLE_FTS5` in its "Code generated by" header, including `lib/sqlite_windows.go` (windows/amd64 and arm64), `lib/sqlite_linux_amd64.go` and `lib/sqlite_darwin_arm64.go` | module source of `modernc.org/sqlite@v1.62.0` |
| Runtime, `CGO_ENABLED=0`, linux/amd64 | `CREATE VIRTUAL TABLE … USING fts5(…, tokenize='unicode61 remove_diacritics 2')`, `MATCH`, `snippet()` and `bm25()` work; `sqlite_version()` is 3.54.1 | throwaway program |
| Cross-builds, `CGO_ENABLED=0` | `GOOS=windows` and `GOOS=darwin GOARCH=arm64` build | same program |
| `RETURNING`, used by the index upsert | needs SQLite 3.35 | https://sqlite.org/lang_returning.html |
| Driver options used | `_pragma=busy_timeout(…)` and `_txlock=immediate` are parsed by the driver; a DSN that is a plain path keeps its query parameters out of the file name | `conn.go` and `sqlite.go` of v1.62.0 |

## Consequences

- The index can use FTS5 directly; no separate search library.
- The `unicode61` tokenizer with `remove_diacritics 2` makes `zamietnuta` match `zamietnutá`, which matters for non-English plans.
- Upgrading the driver needs the same check: the FTS5 flag must stay in the generated headers.
